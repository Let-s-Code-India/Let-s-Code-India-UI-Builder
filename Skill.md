## Stage 2: Global Design Rules & Constraints

### 2.1 Foundational Architectural Mandates
Every interface engineered under this skill must uncompromisingly abide by the following foundational laws:

1. **The Mathematical 60-30-10 Color Proportionality Rule**
   - **60% Dominant Canvas:** Allocated to primary backgrounds, negative whitespace, and immersive atmospheric containers. This prevents visual clutter and establishes breathing room.
   - **30% Structural Architecture:** Allocated to cards, panels, containers, sidebars, and secondary dividing surfaces. It provides structural weight and visual grounding.
   - **10% Focal Intent:** Strictly reserved for high-priority Call-to-Actions (CTAs), live operational indicators, critical system notifications, and interactive focal vectors.
2. **Anti-Flat Surface Enforcement**
   - Ban all unstyled native elements (e.g., raw HTML buttons, default browser inputs, flat borders). Every container must feature intentional depth, backdrop blurs (`backdrop-blur-md`), subtle border tokens (`border border-white/10`), or calculated elevation shadows.
3. **Mobile-First Fluid Responsiveness**
   - Architect every layout from a mobile-first paradigm (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`). Utilize fluid typography (`clamp()`) and flexible grid systems to guarantee flawless scaling across viewport extremes without horizontal overflows.
4. **Semantic DOM & Machine Readability**
   - Enforce rigorous HTML5 semantics (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`) coupled with explicit ARIA attributes (`aria-label`, `aria-expanded`, `aria-describedby`) to ensure pristine screen-reader compatibility and SEO optimization.
5. **Hardware-Accelerated Motion Budgeting**
   - Limit animations to GPU-accelerated CSS properties (`transform`, `opacity`). Avoid heavy layout-shifting animations (`width`, `height`, `margin`) to guarantee a locked 60 FPS rendering performance.

### 2.2 Strict Architectural Prohibitions (What NOT to Do)
- **NEVER use absolute monochrome extremes** (`#000000` or `#FFFFFF`) as primary canvas foundations in dark mode. Always utilize rich charcoal tokens (`#0B0B0B`, `#09090B`, `#121212`) and soft off-whites (`#F4F4F5`, `#FAFAFA`) to eliminate optical vibration.
- **NEVER hardcode arbitrary values** (e.g., `margin-top: 17px;` or random hex codes). All spacing, sizing, and colors must strictly derive from the predefined system scales.
- **NEVER deploy interactive components devoid of micro-states.** Every actionable element must feature explicit, smooth states for `hover`, `focus`, `active`, `disabled`, and `loading`.
- **NEVER rely solely on color to denote semantic status** (e.g., error or success). Always pair color tokens with distinct iconography (`✓`, `✕`, `⚠`, `ℹ`) and contextual text labels for color-blind accessibility.
- **NEVER mix conflicting design paradigms** (e.g., combining harsh Neo-Brutalist borders with soft, ethereal Glassmorphism) within the same view unless explicitly requested as an intentional stylistic juxtaposition.

### 2.3 Component-Level Structural Constraints
1. **Button Engineering:** Minimum touch target height of `44px` to `48px` on mobile viewports. All primary CTAs must integrate smooth transition easing (`transition-all duration-300 ease-in-out`).
2. **Input & Form Architecture:** Must include clear associated labels, visible focus rings (`focus:ring-2 focus:ring-offset-2`), error state borders, and distinct placeholder opacities (`placeholder-zinc-500`).
3. **Card & Bento Architecture:** Must feature balanced padding (`p-6` to `p-8`), consistent border radiuses (`rounded-2xl` or `rounded-3xl`), and subtle hover transformations (`hover:-translate-y-1`).
4. **Typography Line-Height Guardrails:** Body copy must maintain a minimum line-height of `1.5` to `1.7` with a maximum measure (line length) of 65–75 characters for optimal legibility.

## Stage 4: Architectural Prohibitions & Anti-Pattern Guardrails (The 20-Point Master Prohibition Matrix)

### 🚫 The Ultimate Anti-AI & Anti-Mediocrity Firewall
*To ensure that every interface produced under LET-S-CODE-INDIA completely shatters generic LLM stereotypes and matches the elite craftsmanship of tier-1 engineering unicorns (Vercel, Linear, Stripe, Apple), the AI must strictly memorize and enforce the following 20 core prohibitions. Violation of these architectural laws is strictly forbidden.*

---

### 1. Prohibition of "Generic AI Slop" & Cliché Visual Aesthetics
- **Why it is forbidden:** Lazy AI outputs rely on overused purple-to-pink mesh gradients, identical floating device mockups, and uniform border radiuses that immediately scream "generated by an LLM," destroying brand authenticity.
- **What NOT to do:** Never deploy uncalibrated linear gradients across arbitrary containers, never mix conflicting visual weights, and never use unstyled framework defaults.
- **Enforcement Rule:** Every visual element must possess intentional psychological alignment with the requested product archetype (e.g., Deep Navy and precise borders for FinTech; high-contrast terminal precision for developer tools).

### 2. Prohibition of Haphazard Typography & Unscaled Hierarchies
- **Why it is forbidden:** Random font sizing and poor line-height proportions disrupt reading flow, create optical vibration, and reduce readability to absolute zero.
- **What NOT to do:** Never hardcode arbitrary font sizes (e.g., `text-[17px]`), never mix mismatched font families without structural purpose, and never compress line-heights below `1.4` on body text.
- **Enforcement Rule:** All typography scales must strictly map to the 50 Master Typography Systems defined in Stage 3, preserving strict proportional hierarchy from `H1` down to legal captions.

### 3. Prohibition of Low-Contrast, Eye-Strain Palettes
- **Why it is forbidden:** Violating color contrast standards makes interfaces inaccessible to users with visual impairments and causes severe eye strain during extended session times.
- **What NOT to do:** Never use pure absolute black (`#000000`) or pure absolute white (`#FFFFFF`) as flat canvas backgrounds in dark mode. Never place low-contrast secondary text on dark charcoal backgrounds where it becomes unreadable.
- **Enforcement Rule:** Strictly enforce the 60-30-10 proportionality rule. Always verify that text against background surfaces satisfies minimum WCAG AA (`4.5:1` for normal text, `3:1` for large headings).

### 4. Prohibition of "Floating Element Chaos" & Broken Z-Index Layering
- **Why it is forbidden:** Messy z-index layering causes modals to slip behind navigation bars, tooltips to get clipped by parent containers, and interactive dropdowns to break under scrolling.
- **What NOT to do:** Never assign arbitrary z-indices (e.g., `z-[99999]`). Never allow sticky headers to overlap active modal backdrops.
- **Enforcement Rule:** Strictly adhere to the 6-tier Z-Index hierarchy defined in System E: Base canvas (`z-0`), Content containers (`z-10`), Interactive hover layers (`z-20`), Sticky headers (`z-40`), Modals/Overlays (`z-50`), and Tooltips/Toasts (`z-60`).

### 5. Prohibition of Unoptimized, Jank-Inducing Layout Animations
- **Why it is forbidden:** Heavy layout-shifting animations (`width`, `height`, `margin`, `padding`) trigger continuous browser reflows and repaints, dropping frame rates below 60 FPS and causing stuttering on mobile devices.
- **What NOT to do:** Never animate expensive DOM properties like `width`, `height`, or layout box coordinates. Never apply dizzying, non-stop bouncing or spinning animations to core content containers.
- **Enforcement Rule:** Limit all micro-interactions and transitions strictly to GPU-accelerated CSS properties (`transform` and `opacity`) coupled with smooth cubic-bezier easing curves (`transition-all duration-300 ease-in-out`).

### 6. Prohibition of Non-Responsive, Mobile-Breaking Layout Architectures
- **Why it is forbidden:** Designing exclusively for desktop viewports causes horizontal text clipping, overlapping buttons, and broken grids on smartphones, rendering the application unusable for mobile traffic.
- **What NOT to do:** Never use fixed pixel widths for major layout containers (`w-[1200px]`), never omit mobile padding (`px-4 sm:px-6 lg:px-8`), and never allow table or card content to overflow horizontally.
- **Enforcement Rule:** Architect every single component using a strict mobile-first paradigm (`sm:`, `md:`, `lg:`, `xl:`, `2xl:`), ensuring fluid, immaculate scaling from 320px mobile viewports up to 4K ultra-wides.

### 7. Prohibition of Inaccessible, Non-Semantic DOM Structures
- **Why it is forbidden:** Using generic `<div>` wrappers for everything destroys screen reader compatibility, breaks keyboard navigation, and damages search engine optimization (SEO).
- **What NOT to do:** Never build entire pages out of nested `div` containers. Never leave icon-only buttons without descriptive `aria-label` attributes. Never omit visible focus rings on interactive elements.
- **Enforcement Rule:** Enforce strict HTML5 semantic tagging (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`), ensure proper keyboard `tabindex` flows, and guarantee full color-blind safety by pairing semantic colors (red/green) with explicit icons (`✓`, `✕`) and text labels.

### 8. Prohibition of Unhandled Empty States and Loading Voids
- **Why it is forbidden:** Displaying a blank white or black screen while data fetches creates a broken user experience, making the app feel frozen or unresponsive.
- **What NOT to do:** Never leave data containers blank during asynchronous fetching operations. Never use abrupt layout shifts when data finally arrives on the screen.
- **Enforcement Rule:** Every data-driven component must implement skeleton loaders (`animate-pulse bg-zinc-800 rounded-xl`) or elegant, contextual empty-state containers (`border border-dashed border-zinc-800`) with clear call-to-actions.

### 9. Prohibition of Hardcoded Monoliths and Non-Modular Spaghetti Code
- **Why it is forbidden:** Writing massive, multi-thousand-line single-file components makes code impossible to maintain, debug, scale, or collaborate on within open-source ecosystems.
- **What NOT to do:** Never dump entire application layouts, state logic, and styling into a single unreadable file. Never duplicate repetitive styling blocks instead of utilizing reusable components.
- **Enforcement Rule:** Enforce strict atomic component architecture. Break down every interface into modular, single-responsibility React functional components paired with clean TypeScript props and Tailwind utility classes.

### 10. Prohibition of Fake Interactivity and Dead-End UI Elements
- **Why it is forbidden:** Presenting buttons, toggles, or dropdowns that do not react to clicks or keystrokes frustrates users and destroys the illusion of a fully functional product.
- **What NOT to do:** Never deploy static, unlinked buttons in critical conversion paths. Never create dropdown menus that lack active click handlers or keyboard closure listeners.
- **Enforcement Rule:** Every interactive surface must feature explicit hover, focus, active, and execution states. If a feature is a prototype preview, it must display a subtle "Coming Soon" or disabled badge with clear visual cues.

### 11. Prohibition of Inconsistent Spacing and Broken Geometric Rhythms
- **Why it is forbidden:** Random gaps, uneven padding, and misaligned grid cells create a messy, amateurish look that instantly shatters visual balance and hierarchy.
- **What NOT to do:** Never use random margin/padding values (e.g., `p-[13px]`, `m-[7px]`). Never mix incompatible spacing scales within the same structural container.
- **Enforcement Rule:** Strictly utilize Tailwind's proportional spacing scale (multiples of 4: `p-4`, `p-6`, `p-8`, `gap-4`, `space-y-6`) to maintain absolute geometric harmony across all viewports.

### 12. Prohibition of Uncontrolled Content Overflow and Text Wrapping Failures
- **Why it is forbidden:** Long titles, URLs, or user-generated strings breaking out of their container boxes destroy card layouts and ruin the entire screen structure.
- **What NOT to do:** Never allow long unbroken strings or titles to expand past card boundaries. Never omit overflow handling on scrollable data panels.
- **Enforcement Rule:** Enforce defensive CSS styling where necessary (`truncate`, `break-words`, `overflow-hidden`, `max-w-full`) to ensure that even unexpected input data remains neatly bound inside its designated container.

### 13. Prohibition of Static Monolithic Typography Without Responsive Scaling
- **Why it is forbidden:** Large heading texts that look stunning on 4K desktop screens become monstrous text blocks on mobile phones, forcing horizontal scrolling or screen clipping.
- **What NOT to do:** Never use fixed large text sizes (`text-6xl`) on mobile screens without responsive breakpoint modifiers. Never ignore line-height adjustments for massive display headers.
- **Enforcement Rule:** Implement responsive scaling modifiers for all primary display headers (e.g., `text-3xl sm:text-5xl lg:text-7xl`) to ensure proportional typography balance across all screen sizes.

### 14. Prohibition of Uncontrolled Focus Traps and Accessibility Blind Spots
- **Why it is forbidden:** When a modal opens, keyboard users can still tab through background content, or worse, get trapped inside invisible elements, violating core WCAG compliance laws.
- **What NOT to do:** Never leave modal dialogs without active focus trapping. Never disable default outline rings without providing a customized, high-visibility alternative focus state (`focus:ring-2`).
- **Enforcement Rule:** Every overlay, modal, and drawer must programmatically trap keyboard focus upon opening, return focus upon closure, and ensure clear, unmissable focus rings on all interactive elements.

### 15. Prohibition of Uncontrolled Image Aspect Ratio Distortion
- **Why it is forbidden:** Images stretching, squishing, or cropping awkwardly because of missing container bounds make product showcases, avatars, and media cards look severely unprofessional.
- **What NOT to do:** Never drop raw `<img>` tags into layouts without explicit aspect ratios or object-fit constraints. Never allow user profile avatars to deform into ovals.
- **Enforcement Rule:** Always wrap images in controlled container boxes using Tailwind aspect ratios (`aspect-video`, `aspect-square`) combined with object-cover styling (`object-cover w-full h-full`) and rounded clip boundaries.

### 16. Prohibition of Clashing Visual Styles and Theme Contamination
- **Why it is forbidden:** Mixing chaotic design systems—such as placing sharp, high-contrast Neo-Brutalist borders inside a soft, ethereal Glassmorphic SaaS dashboard—creates visual confusion.
- **What NOT to do:** Never combine conflicting design paradigms within the same view unless explicitly commanded as an intentional artistic juxtaposition. Never mix warm earthy color tokens with neon cyberpunk accents randomly.
- **Enforcement Rule:** Maintain absolute stylistic purity. If a project is designated as SaaS/Glass, every single component must adhere strictly to backdrop blurs, subtle borders, and sleek dark surfaces.

### 17. Prohibition of Unstyled Form Inputs and Invisible Validation Errors
- **Why it is forbidden:** Forms that lack clear active borders, error states, or helper descriptions lead to high user drop-off rates and failed submissions.
- **What NOT to do:** Never use default browser input styles. Never show cryptic error codes when form validation fails instead of clear, human-readable helper text.
- **Enforcement Rule:** Every form input must feature explicit focus states (`focus:border-cyan-400 focus:ring-2`), distinct placeholder opacities (`placeholder-zinc-500`), and dedicated error state indicators paired with `aria-describedby` links.

### 18. Prohibition of Performance-Killing Asset Bloat and Uncompressed DOMs
- **Why it is forbidden:** Generating massive, unoptimized DOM trees with hundreds of unnecessary wrapper nodes slows down JavaScript reconciliation and destroys page load speeds.
- **What NOT to do:** Never nest infinite wrapper `div` nodes just to achieve simple centering or padding. Never load massive external images without proper sizing or lazy loading.
- **Enforcement Rule:** Keep DOM structures lean, modular, and optimized. Utilize CSS Grid and Flexbox properties efficiently to achieve complex layouts with minimal structural markup.

### 19. Prohibition of Missing Dark/Light Mode Surface Token Consistency
- **Why it is forbidden:** Hardcoding fixed white or black color classes (`bg-white` or `bg-black`) inside components causes visual shattering when the user toggles between dark and light themes.
- **What NOT to do:** Never use hardcoded absolute color values for structural backgrounds. Never omit surface token mapping for secondary cards and text elements during theme switches.
- **Enforcement Rule:** Strictly utilize semantic design tokens (`--bg-primary`, `--text-main`, `bg-zinc-900 dark:bg-zinc-900`) to guarantee seamless, zero-flash theme adaptation across dark and light modes.

### 20. Prohibition of Abandoned Error Boundaries and Uncaught Exception Crashes
- **Why it is forbidden:** Allowing a minor component rendering error to crash the entire application screen destroys user trust and terminates user sessions abruptly.
- **What NOT to do:** Never leave complex data rendering loops unprotected against null or undefined API payloads. Never omit fallback UI states for dynamic component modules.
- **Enforcement Rule:** Wrap critical functional blocks in robust error boundary structures, implement optional chaining for data properties, and always provide graceful fallback UI states to prevent catastrophic page crashes.
